01 — DATAFLOWHow the four services connect

The services never call each other. Each one writes a JSON file into .corsec/ and the next one reads it back off disk — so the connecting line between any two stages is literally a file path and a TypeScript type. The vertical arrows on the left are ordering only; the labels on them are the conditions under which the next stage runs at all.

02 — SERVICESWhat each one is responsible for

Three deterministic services and one that is allowed to be creative, in a tightly fenced way. The rule in CLAUDE.md is that an LLM may only touch unstructured-text extraction in Hunter (not yet built) and the final PR description in Reporter — nowhere else.

src/hunter/

Hunter

Queries the GitHub Advisory database over GraphQL for advisories published since T−24 h, resolves the union of dependencies and devDependencies against the npm v7+ lockfile, and emits one row per installed package × matching vulnerable range. Multi-node advisories produce multiple rows.

In
GitHub GraphQL · package.json · package-lock.json
Out
hunter-matches.json → MatchedThreat[]
Fails
aborts the run, exit 1
Deterministic
src/cort/

Cort

Fans out to three independent probes under Promise.allSettled: Checkov and tfsec over the Terraform directory, plus read-only AWS context (ALB presence, and Fargate IMDSv2 enforcement inferred from each service's platformVersion, not from the task definition). Findings are then merged on (category, resource).

In
terraform_dir · ECS + ELBv2 Describe* calls
Out
cort-report.json → AggregatedReport
Fails
per-probe; run continues
Deterministic
src/patcher/

Patcher

Collapses every match for a package into one upgrade (highest patched version; the whole group is marked no-fix if any match lacks one), re-reads the lockfile to skip already-resolved entries, cuts a branch only if there is real work, then installs and runs the test command once for the whole batch.

In
hunter-matches.json · npm registry · git
Out
patch-session.json → PatchSession
Fails
synthetic empty session on disk
Deterministic
src/reporter/

Reporter

Chooses template mode when everything is boring (all patches green, zero Cort findings, no non-compliant IMDSv2) and skips the API entirely. Otherwise it trims the three inputs to a payload asserted under 6 000 characters, makes one call, and refuses any response whose five headers are missing or out of order.

In
all three JSON artifacts · Anthropic API
Out
pr-description.md
Fails
aborts, exit 1 — artifacts kept
One LLM call
src/orchestrate.ts

Orchestrator

Not a service so much as the wiring: it owns the output directory, runs each stage exactly once, converts every non-fatal failure into an empty-but-valid input for the next stage, wraps the LLM client to total up tokens, and writes the run summary before every exit path including the aborts.

CLI flags · every stage function (injectable)
Out
orchestration-summary.json · exit code
Fails

Deterministic

04 — DEPLOYMENTWhere this runs and how it gets there

There is no server, no container registry, and nothing to deploy in the usual sense. The unit of deployment is .github/workflows/corsec-pipeline.yml merged to main. Every run provisions a fresh GitHub-hosted VM, installs its own toolchain, does the work, ships two outputs, and is destroyed. Credentials are minted per-run and expire with the job.

05 — CREDENTIALSWhat crosses the boundary, and with what authority

CredentialSupplied byAuthorityUsed by
GITHUB_TOKEN Actions, automatically contents: write · pull-requests: write · id-token: write, job-scoped Hunter's advisory query, and the PR step
AWS_AUDIT_ROLE_ARN repo secret → OIDC assume-role elasticloadbalancing:DescribeLoadBalancers · ecs:ListClusters · ListServices · DescribeServices Cort's AWS context checks
ANTHROPIC_API_KEY repo secret → step env messages.create only Reporter, at most once per run

Cort never mutates AWS state — the entire IAM policy is Describe*. The trust policy scopes the federated identity with a StringLike on token.actions.githubusercontent.com:sub, which can be tightened from repo:OWNER/REPO:* to a single ref if you only ever want scheduled runs on main to hold credentials.

06 — FAILUREWhat happens when a connection breaks

Only two stages can end the run. Everything else degrades into a valid-but-empty input so the remaining stages still produce something a human can read.

ConditionBehaviourRun
Hunter throws summary written, no later stage invoked exit 1
Hunter finds zero matches nothing to patch; stops cleanly before Cort exit 0
Checkov, tfsec or AWS probe fails that probe degrades to an empty report; the other two still aggregate continues
No terraform_dir supplied Cort skipped entirely; an empty AggregatedReport is still persisted continues
Patcher throws synthetic empty PatchSession written to disk so Reporter can still read it continues
Reporter's output fails header validation no repair attempted; all upstream artifacts are preserved and uploaded exit 1
No ANTHROPIC_API_KEY, template mode chosen the API is never called; deterministic markdown is rendered instead exit 0

Dry-run is the default and should stay that way for a while. With dry_run: true the pipeline produces and uploads every artifact but pushes no branch and opens no PR. The recommendation in the README is at least a week of six-hourly runs read like a code review before flipping it — watching the [llm-cost] line for token drift, the stage-duration table for flakiness, and pr-description.md for invented facts.
